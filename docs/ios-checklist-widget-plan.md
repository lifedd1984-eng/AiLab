# 체크리스트 앱 + 홈 화면 위젯 기획안

문서 버전: v2.0 (기획 확정본) · 작성일: 2026-08-09 · 대상 플랫폼: iOS (iPhone 우선)
상태: 구현 착수 가능. 단, §14 "열린 질문"은 사용자 확인 후 반영.

---

## 1. 한 줄 요약

할 일과 살 것을 한 줄씩 적고, 끝나면 체크해서 지우는 **아주 단순한 체크리스트 앱**.
핵심 차별점은 **앱을 열지 않고 홈 화면 위젯에서 바로 체크**할 수 있다는 것 (iOS 17+ 인터랙티브 위젯).

---

## 2. 배경과 문제 정의

- 기존 할 일 앱은 프로젝트·태그·반복·협업 등 기능이 많아 "우유 사기" 한 줄 적기에도 부담이 크다.
- 정작 필요한 순간(마트 계산대 앞, 집 나서기 직전)에는 **앱을 여는 3초조차 마찰이다.**
- 홈 화면에서 목록이 항상 보이고 **탭 한 번으로 체크**되면 그 마찰이 사라진다.

**해결하려는 것**: "적는 마찰"과 "확인/완료 마찰"을 동시에 0에 가깝게 만든다.

### 제품 원칙 (구현 중 판단이 갈릴 때의 기준)
1. **위젯이 주인공, 앱은 입력기.** 기능 추가로 이 구도가 흐려지면 하지 않는다.
2. **탭 수 최소.** 어떤 핵심 동작도 2탭을 넘기지 않는다.
3. **실수 복구 가능.** 지우는 동작은 항상 되돌릴 수 있다.

---

## 3. 목표 / 하지 않을 것

### 목표 (MVP)
1. 앱 실행 → 첫 항목 저장까지 3초 이내.
2. 홈 화면 위젯에서 앱 실행 없이 체크할 수 있다.
3. 체크한 항목은 목록에서 사라지고, 언제든 되돌릴 수 있다.

### 이번에 하지 않을 것 (명시적 제외)
- 계정/로그인, 서버, 공유·협업
- 반복 일정, 알림, 위치 기반 리마인더
- 태그·우선순위·자동 정렬 등 고급 분류
- 여러 개의 리스트 (v1.0은 단일 리스트 — §14 Q2 참고)
- Android / 웹 / Mac / Watch

> 뺀 기능은 "안 만든다"가 아니라 **v1.1 이후로 미룬다**. §6.2~6.3 참고.

## 4. 타깃 사용자와 사용 시나리오

**주 사용자**: 복잡한 생산성 앱에 지친 일반 사용자. 하루 3~10개 항목 수준.

| # | 상황 | 흐름 | 성공 조건 |
|---|------|------|-----------|
| S1 | 자기 전 내일 할 일 정리 | 앱 열기 → 연속으로 3~4개 입력 → 종료 | 키보드가 내려가지 않고 연속 입력 |
| S2 | **마트에서 장보기** | 위젯 보면서 담을 때마다 위젯에서 바로 체크 | 앱을 한 번도 열지 않음 |
| S3 | 외출 직전 확인 | 홈 화면 훑기만 함 | 위젯 정보가 최신 상태 |
| S4 | 잘못 체크함 | 앱의 "완료됨" 섹션에서 되돌림 | 2탭 이내 복원 |

**S2가 이 앱의 존재 이유다.** 모든 설계 판단은 S2를 기준으로 한다.

## 5. 위젯 규격: 요청사항과 iOS 제약, 그리고 결정

### 5.1 원 요청
"앱 아이콘 4~5개 폭, 1행짜리 긴 막대(1×5) 위젯"

### 5.2 iOS의 제약 (사실관계 — 변경 불가)
iOS 위젯은 개발자가 크기를 자유롭게 정할 수 없고, 시스템 규격 중에서만 선택한다.

| 규격 | 홈 화면 점유 (아이콘 기준) | 비고 |
|------|---------------------------|------|
| `systemSmall` | 2열 × 2행 | 정사각형 |
| **`systemMedium`** | **4열 × 2행** | **가로로 긴 막대 — 요청에 가장 근접** |
| `systemLarge` | 4열 × 4행 | 세로로 큼 |
| `systemExtraLarge` | — | iPad 전용, iPhone 미지원 |

- iPhone 홈 화면은 **가로 4열**이므로 "5열 폭"은 물리적으로 불가능.
- **1행 높이 위젯은 iOS에 존재하지 않는다.** 홈 화면 위젯의 최소 높이는 2행.

### 5.3 결정
1. **`systemMedium`(4×2)을 메인 위젯으로 확정.** 홈 화면에서 가로로 길쭉한 막대 형태 — "긴 위젯" 의도에 가장 가깝고, 2행 높이 덕분에 오히려 항목 3개를 체크 가능한 크기로 보여줄 수 있다 (1행이었다면 체크박스 탭 영역 확보가 불가능했을 것).
2. **`systemLarge`(4×4)도 v1.0에 동시 제공.** 같은 뷰 코드에 행 수만 다르므로(3개 → 8개) 추가 비용이 거의 없고, "장보기 목록이 길 때 3개는 부족하다"는 예상 불만의 대응책이다.
3. 잠금화면 위젯(`accessoryInline` / `accessoryRectangular`)은 **v1.1로 이동.** 표시 전용(잠금화면에서는 체크 불가)이라 핵심 가치와 무관하고, MVP 범위를 줄이는 것이 우선이다.

> 사용자 커뮤니케이션 가이드: "1×5는 iOS가 허용하지 않는다"가 아니라 "**iOS에서 가장 길고 낮은 위젯이 4×2이고, 그 안에 할 일 3개를 바로 체크할 수 있게 넣었다**"로 설명한다.

## 6. 기능 명세

각 기능에 수용 기준(AC)을 명시한다. 구현 완료 판정은 AC 기준.

### 6.1 MVP (v1.0)

#### F1. 항목 추가
- 메인 화면 상단에 고정된 입력창. 앱 진입 시 목록이 비어 있으면 자동 포커스, 비어 있지 않으면 포커스 없이 표시(목록 확인이 먼저인 경우 배려).
- return 키(레이블: "추가")로 저장. 저장 후 입력창은 비워지고 **포커스 유지** → 연속 입력.
- 공백만 입력 시 저장하지 않음. 최대 100자(초과분 입력 차단).
- 새 항목은 **목록 맨 아래**에 추가된다 (적은 순서 = 처리 순서라는 멘탈 모델).
- AC: 앱 콜드 스타트 → 첫 항목 저장까지 3초 이내. 5개 연속 입력 시 키보드가 한 번도 내려가지 않는다.

#### F2. 항목 체크 (앱 내)
- 행 왼쪽 원형 체크박스 탭 → 체크 표시 + 취소선 → **0.4초 후** 목록에서 사라져 "완료됨" 섹션으로 이동.
- 0.4초 안에 다시 탭하면 체크 취소(이동 안 함).
- AC: 체크 → 사라짐 애니메이션이 끊기지 않고, 연속으로 빠르게 여러 개 체크해도 유실 없음.

#### F3. 실행 취소
- 항목이 완료 처리되어 사라진 직후, 하단에 "완료: {제목} — 실행 취소" 스낵바 5초 노출.
- 여러 개 연속 체크 시 스낵바는 최신 항목 기준으로 갱신되되, 실행 취소는 **마지막 1건**만 대상 (이전 것은 F4로 복원).
- AC: 실행 취소 탭 시 항목이 원래 위치(sortOrder)로 복귀.

#### F4. 완료됨 섹션
- 메인 화면 하단에 "완료됨 N개" 접힌 섹션. 탭하면 인라인으로 펼쳐짐 (별도 화면 아님 — 화면 수 최소화).
- 완료 항목은 완료 시각 역순 표시. 체크박스 탭으로 즉시 미완료 복원.
- 완료 후 **7일** 경과 항목은 앱 실행 시점에 영구 삭제 (§14 Q3).
- AC: 잘못 체크한 항목을 2탭(펼치기 → 체크 해제)으로 복원 가능.

#### F5. 항목 수정 / 삭제
- **텍스트 영역 탭** → 해당 행이 인라인 편집 모드로 전환(체크박스 탭과 영역 분리).
- **왼쪽으로 스와이프** → 삭제 버튼. 삭제 시에도 F3 스낵바로 실행 취소 제공.
- AC: 체크하려다 편집 모드로 들어가는 오탭이 발생하지 않도록, 체크박스 탭 영역은 최소 44×44pt.

#### F6. 순서 변경
- 행을 **길게 눌러 드래그** (SwiftUI List 표준 reorder). 길게 누르기는 순서 변경 전용 — 편집은 F5의 탭으로만 진입해 제스처 충돌을 없앤다.
- AC: 드래그 후 순서가 앱 재실행·위젯에 그대로 반영.

#### F7. 위젯 표시 (`systemMedium` / `systemLarge`)
- 미완료 항목을 sortOrder 순으로 표시. Medium 3개 / Large 8개 + "+N개 더".
- 빈 상태: "할 일 끝! ✨" + 탭하면 앱의 입력창으로 이동.
- AC: 앱에서 추가/체크/삭제/순서 변경 후 홈 화면 복귀 시 위젯이 갱신되어 있다.

#### F8. 위젯 내 체크 — 핵심 기능
- 위젯 각 행의 체크박스는 `Button(intent:)` (AppIntent). 탭 즉시:
  1. 체크 표시 + 취소선으로 시각 피드백 (위젯 뷰가 즉시 리렌더링됨)
  2. 저장소에 완료 기록
  3. 다음 타임라인 렌더링에서 목록에서 제거되고 다음 항목이 올라옴
- **위젯에는 실행 취소 UI를 두지 않는다.** 좁은 공간에 undo를 넣으면 오탭 위험이 더 커진다. 복구는 앱의 F4로. 대신 체크 직후 항목이 즉시 사라지지 않고 취소선 상태로 한 프레임 보여 "뭘 체크했는지" 인지시킨다.
- AC: 앱이 백그라운드에 없어도(스와이프 종료 상태) 위젯 체크가 동작한다. 체크 → 시각 반영 1초 이내.

#### F9. 위젯 → 앱 딥링크
- 탭 영역별 라우팅 (`widgetURL` / `Link`):

| 탭 위치 | 동작 | URL |
|---------|------|-----|
| 행의 체크박스 | F8 (앱 안 열림) | — (AppIntent) |
| 행의 텍스트 | 앱 열기 → 해당 항목으로 스크롤 | `checklist://item/{uuid}` |
| 헤더·빈 영역·빈 상태 | 앱 열기 → 입력창 포커스 | `checklist://add` |

- AC: 각 영역 탭이 명세대로 라우팅. 존재하지 않는 uuid는 메인 화면으로 폴백.

### 6.2 v1.1 (출시 직후)
- 리스트 분리: "할 일" / "장보기" 2개, 위젯 편집(길게 누르기 → 편집)에서 표시할 리스트 선택 (`WidgetConfigurationIntent`)
- 잠금화면 위젯: `accessoryRectangular`(항목 2줄) + `accessoryInline`("우유 사기 외 3개") — 표시 전용
- 위젯 테마 2~3종 (라이트/다크 외 강조색)

### 6.3 v2 이후 후보
- iCloud 동기화(CloudKit) → 이후 Apple Watch 앱
- Siri / 단축어 연동 ("장보기에 우유 추가") — F8의 AppIntent 재사용 가능

## 7. 화면 설계

### 7.1 메인 화면 (앱은 이 한 화면 + 설정 시트가 전부)

```
┌──────────────────────────────┐
│  체크리스트              ⚙︎  │  ← 타이틀 / 설정 시트
│                              │
│  ┌────────────────────────┐  │
│  │ + 새 항목 입력…        │  │  ← 상단 고정, return="추가", 연속 입력
│  └────────────────────────┘  │
│                              │
│  ◯  우유 사기                │  ← ◯ 탭=체크(44pt), 텍스트 탭=인라인 편집
│  ◯  세탁물 찾기              │     ← 스와이프=삭제, 길게+드래그=순서
│  ◯  전기요금 납부            │
│  ◯  병원 예약 전화           │
│                              │
│  ─────────────────────────   │
│  완료됨 3 ›                  │  ← 탭하면 인라인 펼침, 체크 해제로 복원
│                              │
│  [완료: 우유 사기  실행 취소] │  ← 스낵바 5초
└──────────────────────────────┘
```

- 설정 시트 내용(v1.0): 완료 항목 보관 기간 안내, 앱 버전, 문의 메일 링크. 그 이상 넣지 않는다.
- 빈 상태(항목 0개): 일러스트 없이 "아래가 아니라 위! 입력창에 첫 항목을 적어보세요" 한 줄 + 입력창 자동 포커스.

### 7.2 홈 화면 위젯 — `systemMedium` (4×2, 메인)

```
┌───────────────────────────────────────────────┐
│  체크리스트                            4개     │  ← 헤더 탭 → checklist://add
│  ◯  우유 사기                                  │
│  ◯  세탁물 찾기                                │  ← ◯ 탭 = AppIntent 즉시 체크
│  ◯  전기요금 납부                    +1개 더   │     텍스트 탭 = 앱에서 열기
└───────────────────────────────────────────────┘
```

- 행 3개 + 남은 개수. 체크박스 탭 영역 최소 28pt 원 + 상하 패딩으로 실질 40pt 이상 확보.
- 텍스트는 1줄 말줄임. 폰트 `.subheadline` 기준, 다이나믹 타입 XL 이상에서는 2개 행으로 자동 감소 허용.
- 빈 상태: "할 일 끝! ✨" 중앙 표시, 전체 탭 → `checklist://add`.

### 7.3 홈 화면 위젯 — `systemLarge` (4×4, 보조)

Medium과 동일 레이아웃에 행 8개 + "+N개 더". 장보기처럼 목록이 길 때 사용.

### 7.4 위젯 갤러리 문구
- 이름: "빠른 체크리스트" / 설명: "앱을 열지 않고 홈 화면에서 바로 체크하세요."

## 8. 데이터 모델

```swift
@Model
final class ChecklistItem {
    var id: UUID
    var title: String        // 1...100자
    var isDone: Bool
    var createdAt: Date
    var completedAt: Date?   // isDone == true일 때만 값 존재
    var sortOrder: Int       // 미완료 목록 표시 순서. 새 항목 = max+1
}
```

- 저장소: **App Group 컨테이너 내 JSON 파일** (Codable). — *구현 시 변경(2026-08-09): 원안은 SwiftData였으나, 200개 이하 목록엔 성능 차이가 없고 위젯 익스텐션과의 컨테이너 공유 설정·스키마 관리 공수가 통째로 사라져 JSON 파일로 확정. 필드 구성은 아래와 동일.*
- 앱과 위젯 익스텐션은 **별개 프로세스**이므로, App Group 없이는 저장소 공유가 불가능하다. 설정 누락 시 위젯이 항상 빈 목록 → **1단계에서 최우선 검증**.
- `completedAt`이 7일 이전인 항목은 앱 실행 시 삭제 (v1.0에서 기간 설정 UI는 없음).
- 리스트 분리(v1.1) 대비: v1.1에서 `listKind` 필드를 추가하는 마이그레이션으로 대응. v1.0 스키마에 미리 넣지 않는다(죽은 필드 금지).

## 9. 기술 설계

| 영역 | 선택 | 이유 |
|------|------|------|
| 최소 지원 버전 | **iOS 17.0+** | 위젯 내 상호작용(Button + AppIntent)이 iOS 17부터. 핵심 기능이므로 타협 불가 |
| UI | SwiftUI | 앱/위젯 뷰 코드 공유 |
| 위젯 | WidgetKit (`systemMedium`, `systemLarge`) | |
| 위젯 상호작용 | **AppIntent** — `CompleteItemIntent(id:)` | 위젯 버튼 → Intent가 익스텐션 프로세스에서 저장소 수정 → 타임라인 자동 갱신 |
| 저장소 | JSON 파일 + App Group (구현 시 SwiftData에서 변경 — §8 참고) | 서버 없이 앱↔위젯 공유, 공수 최소 |
| 동기화 | 없음 (v1.0 로컬 전용) | v2에서 CloudKit |

### 위젯 갱신 정책
- 앱에서 데이터 변경 시(추가/체크/삭제/순서/편집) 저장 직후 `WidgetCenter.shared.reloadAllTimelines()`.
- 위젯에서 체크 시: Intent `perform()`에서 저장 → 시스템이 해당 위젯을 즉시 리렌더링 (수동 reload 불필요, 단 다른 크기 위젯 동기화 위해 reload 호출 권장).
- 시간 기반 타임라인은 단일 엔트리(갱신 예약 없음)로 유지 — 데이터는 이벤트로만 바뀌므로 시스템 갱신 예산을 소모할 이유가 없다. 7일 정리는 앱 실행 시 수행.

### 프로젝트 구조
```
Checklist/
├── ChecklistApp/          # 메인 앱 타깃
├── ChecklistWidget/       # 위젯 익스텐션 타깃
└── ChecklistKit/          # 공유 로컬 패키지 (SPM)
    ├── Models/            # ChecklistItem
    ├── Store/             # SwiftData 컨테이너(App Group), CRUD, 7일 정리
    ├── Intents/           # CompleteItemIntent
    └── DeepLink/          # checklist:// 파싱
```

### 구현 순서 권고 (리스크 선검증)
1. App Group + SwiftData 컨테이너 + **위젯에서 AppIntent로 체크되는 최소 프로토타입** (기술 리스크의 80%)
2. 메인 화면 F1~F6
3. 위젯 레이아웃 완성 F7·F9, 딥링크
4. 폴리시·엣지 케이스·접근성

## 10. 엣지 케이스

| 상황 | 동작 |
|------|------|
| 위젯 체크와 앱 조작이 거의 동시 발생 | SwiftData 저장소가 단일 소스. Intent와 앱 모두 저장 직후 reload → 마지막 쓰기 승리, 유실 없음 |
| 위젯 체크한 항목을 앱에서 이미 삭제함 | Intent에서 id 조회 실패 시 조용히 무시(no-op), 타임라인만 갱신 |
| 항목 100자 초과 붙여넣기 | 100자에서 잘라 저장하고 편집 모드 유지 |
| 항목 수 매우 많음(100+) | 앱은 스크롤로 전부 표시. 위젯은 3/8개 + "+N개 더". 성능 목표는 200개까지 무지연 |
| 다이나믹 타입 최대 | 앱: 표준 대응. 위젯: 행 수 자동 감소(Medium 3→2) |
| App Group 컨테이너 초기화 실패 | 위젯: "앱을 열어 시작하세요" 표시. 앱: 재시도 후 실패 시 로컬 폴백 없이 오류 안내(무음 데이터 분기 금지) |

## 15. v2 기획 변경 (2026-08-09 사용자 피드백 — 목업 v1 확인 후)

세 가지 요청으로 §6~§8의 일부가 대체된다. 목업 v2(`docs/mockups/v2.html`)가 확정 기준.

1. **대분류 카테고리 도입** — "살 것"·"할 것" 같은 카테고리를 만들고, 선택하면 그 소분류(항목) 목록이 표시된다. 앱 상단에 카테고리 칩 행 + ＋ 추가(이름·아이콘). §14 Q2의 "단일 리스트" 결정을 뒤집어 **카테고리를 v1.0에 포함**한다. 위젯 상단에도 **카테고리 칩 행**이 표시되며, 칩을 탭하면 앱을 열지 않고 위젯 안에서 해당 카테고리로 전환된다(`SelectCategoryIntent` — 체크와 같은 AppIntent 버튼 방식, 선택 상태는 App Group에 저장). 위젯 편집 설정은 불필요.
2. **체크 후 사라지지 않음** — F2의 "0.4초 후 완료됨 섹션 이동"을 폐기. 체크하면 **그 자리에서 취소선 유지**, 재탭으로 해제. 앱·위젯 동일. 실행 취소 스낵바(F3)는 불필요해져 삭제. 위젯 헤더의 남은 개수는 미체크 항목만 센다.
3. **완료 히스토리** — "완료됨 접힌 섹션"(F4) 대신 별도 **히스토리 화면**(🕘). 줄 그어진 항목은 "체크된 N개 정리" 버튼으로 목록에서 치우며, 삭제가 아니라 히스토리로 이동. 히스토리는 날짜별 그룹(완료 시각·카테고리 표시), 항목별 "되돌리기"로 복원. 7일 자동 삭제(Q3)는 폐기 — 히스토리는 무기한 보관.

데이터 모델 영향: `Category { id, name, icon, sortOrder }` 추가, `ChecklistItem`에 `categoryID` 추가, 완료 항목은 `archived` 플래그(정리 전 `isDone`, 정리 후 `archived`)로 구분. 일정 영향 약 +3~4일.

4. **Android 지원 추가** (2026-08-09 확정) — §3의 "Android 제외"를 뒤집어 v1.0에 포함. 구현 방식은 **네이티브 2벌**: iOS(SwiftUI + WidgetKit, `ios/`) / Android(Jetpack Compose + Glance 위젯, `android/`). 크로스플랫폼 프레임워크는 배제 — 핵심인 홈 화면 위젯이 양쪽 모두 네이티브 필수라 공수 절감 효과가 없고 툴체인만 늘어난다. 두 구현은 동일한 데이터 스키마·기능 명세를 공유한다. Android는 위젯이 앱과 같은 프로세스라 App Group이 불필요하고, 위젯 자유 리사이즈 덕분에 **원 요청이었던 1행 "긴 막대" 형태도 가능**하다.
5. **PWA(웹 앱) 추가** (2026-08-09) — iOS 설치 마찰(Apple 개발자 계정·서명·TestFlight 승인 대기)이 크다는 피드백으로, `pwa/`에 별도 웹 버전 추가. 회원가입·서명·심사 없이 브라우저에서 "홈 화면에 추가"만으로 설치되는 PWA. **단, 홈 화면 위젯은 iOS/Android 정책상 PWA로 구현 불가** — 위젯이 핵심 가치인 이 앱에서 PWA는 네이티브 앱의 대체재가 아니라 "지금 바로 체험" 용도의 보조 배포 경로. 데이터는 기기 로컬(localStorage) 전용, 기기 간 동기화 없음. GitHub Pages로 자동 배포.
